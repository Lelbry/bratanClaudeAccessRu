# Telegram Desktop через LocalProxyForClaude

Как направить трафик Telegram Desktop через наш SSH-туннель и tinyproxy.

## Что заработает и что нет

✅ **Работает через прокси:**
- Все сообщения, файлы, фото, видео
- Секретные чаты
- Каналы, боты, стикеры
- Голосовые/видеосообщения (не путать со звонками)

❌ **НЕ работает через HTTP-прокси:**
- **Голосовые и видеозвонки** (используют UDP peer-to-peer, HTTP CONNECT только TCP)
- Звонки автоматически fallback-ятся: если у собеседника получится напрямую — соединятся минуя прокси; если нет — звонок не пройдёт

Если нужны и звонки — используй SOCKS5 (через SSH `-D`), но это отдельная история.

---

## Настройка (2 минуты)

### 1. Убедись что туннель поднят
```powershell
cd <ROOT>
.\status.ps1
```
Должно быть `[tunnel] UP` и `[proxy] OK`.

### 2. В Telegram Desktop

1. Открой Telegram Desktop
2. **☰** (гамбургер меню, слева сверху) → **Settings**
3. **Advanced** (справа в списке)
4. Прокрути вниз до **Connection type** → **Use custom proxy**
5. В открывшемся окне:
   - Нажми **Add proxy**
   - Тип: ◉ **HTTP**
   - **Hostname:** `127.0.0.1`
   - **Port:** `8888`
   - **Username / Password:** оставить пустыми
   - Нажать **Save**
6. Убедись что этот прокси **выбран** (галочка)
7. Опционально: включить **Use for calls** — но помни, звонки всё равно не пойдут через HTTP CONNECT, это скорее «пусть Telegram знает что мы хотим использовать прокси всегда где можно»

### 3. Проверка

Внизу окна настроек Telegram будет надпись:
- **Connected** (зелёная) → всё работает через прокси
- **Connecting...** больше 5-10 сек → туннель упал / прокси не отвечает → проверь `.\status.ps1`

Или в любом чате отправь себе сообщение — если ушло мгновенно, значит всё ок.

## Проверка что реально идёт через сервер

Пока Telegram подключён через прокси, на сервере можно смотреть логи tinyproxy — там будут появляться CONNECT-запросы к Telegram-серверам:

```powershell
$keyPath = "<ROOT>\keys\id_ed25519_claude"
ssh -i $keyPath root@YOUR_SERVER_IP "tail -f /var/log/tinyproxy/tinyproxy.log | grep -i telegram"
```

Или так, без grep, чтобы увидеть все CONNECT-запросы:
```powershell
ssh -i $keyPath root@YOUR_SERVER_IP "tail -f /var/log/tinyproxy/tinyproxy.log"
```

Ты увидишь строки вида:
```
CONNECT   Sep 04 18:15:23 [xxx]: Connect (file descriptor N): 149.154.167.99:443
```
где `149.154.167.99` — это Telegram DC (data center). У них диапазоны:
- 149.154.160.0/20 — DC 1-5
- 91.108.4.0/22 — DC 4-5

## Если что-то не подключается

**Telegram висит на «Connecting...»**
- `.\status.ps1` — туннель жив?
- Если UP: перезапусти Telegram (иногда он не переподключается автоматом после падения прокси)
- Если DOWN: `.\start-tunnel.ps1`

**Всё соединилось, но каналы медленно грузятся**
- Медиа Telegram использует CDN. У нас все Telegram-порты уже разрешены (443, 80, 5222, 5228). Если конкретный порт залип — можно временно поставить `Auto` в настройках Telegram, посмотреть работает ли без прокси, потом обратно.

**Хочу вернуть Telegram напрямую (без прокси)**
- Settings → Advanced → Connection type → выбери **Auto**
- Или в списке прокси убери галочку с нашего HTTP прокси

## Как отключить прокси для Telegram, но оставить его настроенным
Settings → Advanced → Connection type → Auto. Прокси в списке остаётся, но не используется. Включить обратно в один клик через тот же экран.

## Технические детали (для любопытных)

**Почему CONNECT работает для не-HTTP протокола (MTProto)?**
HTTP-прокси-метод `CONNECT hostname:port HTTP/1.1` открывает голый TCP-туннель до целевого хоста. После этого прокси перестаёт вмешиваться и просто гоняет байты в обе стороны. Telegram шлёт свой MTProto трафик через этот туннель — прокси об этом ничего не знает.

**Почему звонки не работают?**
Голосовые звонки используют UDP + WebRTC для peer-to-peer соединения (низкая задержка). UDP через HTTP-прокси не проходит вообще — протокол HTTP CONNECT только для TCP. Telegram при неудаче P2P fallback-ится на TCP relay через свои сервера, но это тоже требует поддержки не через нашу CONNECT-прокси.

Решение (если очень нужно): SSH SOCKS5 через `ssh -D 1080`, но SOCKS5 в Telegram Desktop поддерживается тоже только для TCP — UDP звонки всё равно не пройдут. Для UDP нужен полноценный VPN (WireGuard).
